# Common-base practices audit

- **Repo:** `recon-breaks-engine`
- **Catalog id:** F1 (package `recon_breaks_engine`, env prefix `RECONBREAKS`)
- **Catalogue reference:** [`common-base-practices.md`](https://github.com/portable-genai/.github/blob/main/common-base-practices.md) (checks A1..G7)

This file ships PRE-FILLED with the verdicts the template can honestly claim on the day the repo
is rendered, so a new repo never enters the audit matrix owing an unwritten audit. It is not a
claim that the repo was inspected: re-run each check against the tree and correct the row before
citing this as evidence. The rows marked GAP are the day-one work list, in priority order.

Applicability: a rendered repo ships an `agent/` surface (tool functions plus the A2A card
served at `/.well-known/agent-card.json`), a `ui/` micro-frontend and a full `scripts/` demo
surface, so `[ui]` and `[demo]` checks apply on day one. `infra/terraform/` is a filled-in
stack (region allowlist, org policy, CMEK, VPC-SC, locked WORM logging, an internal-load-balancer
serving edge behind IAP and Cloud Armor), so the `[infra]` checks apply in full. What is still
missing there is a BUILD gate rather than a resource: `infra/terraform/production_edge.tftest.hcl`
is a credential-free `terraform test` suite that no `make` target and no workflow invokes, so the
posture is asserted rather than guarded, and the P-03 row in `COMPLIANCE.md` stays Partial for
that reason. The agent is scaffolded and tested but not yet registered with Hrz3; see the R4 row
in `COMPLIANCE.md`. A repo with no user-facing surface should run `make drop-ui` and mark the
`[ui]` rows N/A, rather than leaving a UI half-wired.
**Load-bearing** checks (a FAIL breaks a shared catalog guarantee) are A1-A6, C1-C5, D1-D3 and E1.
